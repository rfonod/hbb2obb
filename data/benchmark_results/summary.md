Runs are ranked by average IoU alone, descending, at full precision; the table prints five
decimals so that two rows which differ are never shown as if they did not. Nothing else
enters the ordering.

Read that ordering against its own resolution. The ± column is the box-to-box spread, which
stays wide however many boxes are scored and is not an error bar on the mean; the standard
error of the mean is `sem_iou` in each `results.yaml` and is smaller by the square root of
the box count. Runs closer together than that are tied, not ranked, and the accuracy-against-
compute figure draws the band so this is visible rather than inferred.

The angle and IoU>=0.9 columns are reported, never optimised. Mean IoU saturates on tight
boxes, so they are what to read when runs tie on it. The orientation column is the 90th
percentile rather than the median: on a set whose ground truth is largely axis-aligned, which
is what a drone squared to a road grid produces, most pairs score exactly zero and the median
is zero at every setting.

## Per-run detail

Each `<run>/` folder holds `run_config.yaml` (the resolved settings and the host it ran on),
`results.yaml` (every grid point), `summary.txt` (the same, human readable) and
`plot.png` (average IoU against scale factor, coloured by image size).

The time column is one pass over the image set with the models already loaded. Checkpoint
loading is timed separately, as `model_load_seconds` in each `results.yaml`.
